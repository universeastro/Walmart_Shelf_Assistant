### 2.1 `B模板.xls` 自身的结构：两个块 + 3 行间隔

`B模板.xls` 不是普通数据表。它中间恰有 **3 个空行（R286–R288，三列全空）**，
把 692 条数据切成两块：

| 块 | 行范围 | 行数 | `平台SKU` 前缀 |
|---|---|---|---|
| 第 1 块 | R2 – R285 | 284 | `XPY0909` → `XPY1192`（逐行 +1，恰 284 个） |
| 间隔 | R286 – R288 | 3 | 空 |
| 第 2 块 | R289 – R696 | 408 | `XPY0909` → `XPY1316`（逐行 +1，恰 408 个） |

第 2 块起始行 **R289 = 285 + 4**，与项目既有追加规则
「新批次从末行 L 的 **L+4** 开始」（见 `docs/APPEND_VERIFICATION.md`）**完全吻合**——
**说明该文件本身就是由追加逻辑（或同一约定）累积而成**。
这是 §8.1 第 2 项判为「追加」的主要依据。

> 注：两块的前缀都从 `XPY0909` 起算，故 `XPY0909`–`XPY1192` 这 284 个前缀在两块中各出现一次，
> 扫描时会表现为「每个前缀恰好出现 2 次」。

1. **两套 A 表的 D 列表头名不一致。** `文件/01/A模板01.xls` D1 = `自定义SKU`；
   `文件/02/A模板02.xls` D1 = `自定义`。按表头名匹配时同一套代码在两份 A 表上行为不同。
2. **`A模板02.xls` 正好压在行数上限。** 共 373 行（表头 1 + 数据 372），
   `AGENTS.md` 记录的模板容量实测上限恰为 **372 行**，**没有余量**。
3. **`A模板02.xls` 有表头为空但带数据的列。** `C列` 与 `E列` 表头为空，每行却有值
   （`C2=XPY0907`、`E2=XPY0907ACP260824015`）。表头为空意味着**表头名匹配必然失败**，
   只能靠列字母兜底——与「列字母不可信」直接冲突。文档 01 的「E列 → Variant Group ID」
   正是这一类，建议在 `PROJECT.md` 中单列。
4. **`B模板02.xlsx` 自带 13 行样例数据**（R7–R19），`B模板01.xlsx` 则为空模板。
   已有「B 模板追加写入」能力（见 `docs/APPEND_VERIFICATION.md`），
   但对 B02 **追加还是覆盖**需明确，否则会污染样例数据或产生重复行。
5. **`B模板.xls` 已有 692 条数据且与 A02 交集为 0**——若采用追加语义，
   追加后行数将达 1064 行，需确认目标表是否有容量上限。
6. **三处输入尚未入库**：`文件/02/B模板.xls`、`文件/02/项目需求文档02.docx`
   （后者当前被 Word 打开，存在 `~$` 锁文件），以及 `文件/01/`、`文件/02/` 的重组本身。
   **Codex 动工前应先入库**，否则验证无锚点。
7. **两版文档第 3 条有同一处笔误**：「若是表头行不可以映射到，则再采用**表头行**进行映射」
   ——第二处应为「**列标行**」，否则该条自相矛盾。现有实现的 `fallback-column`
   已按「列标兜底」处理，属文档笔误、实现正确，建议澄清文档而非改代码。

### 11.1 三个阻塞点

**B1 — `Find-TargetSheet` 直接抛异常（第 86–116 行）。**
该函数对工作簿内每个可见工作表打分：`sku` **+3**、`product name` **+3**、
`site description` **+2**、`main image url` **+2**；第 112 行要求 `$bestScore -ge 5`，
否则 `throw '未找到包含 SKU、Product Name 等字段的目标工作表。'`。

`B模板.xls` 全表只有 `A1 = SKU` 一个命中项 →
**得分 3 < 5 → 抛异常**。（`B1 = 平台SKU` 归一化后是 `平台sku`，不等于 `sku`，+0。）

**B2 — `Find-TargetColumns` 也会抛异常（第 118–186 行）。**
第 129–141 行扫描前 10 行，要求**同一行内**同时出现 `sku` **和** `product name`
才算叶子表头行；否则第 142 行 `throw '目标工作表没有可识别的字段表头。'`。

`B模板.xls` 第 1 行是 `SKU` + `平台SKU`，**没有 `Product Name`** → 抛异常。

**B3 — `$sourceDefinitions` 是文档 01 的硬编码契约（第 313–337 行）。**
18 条定义全部面向 `B模板01/02.xlsx`；文档 02 只需要 2 条。
其中第 314 行 `自定义SKU → SKU`（fallback `D`）在 `A模板02` 上会把 **D 列写进 SKU 列**、
并完全忽略 A 列 `SKU`——正是本文件 §7 与既有 T02 记录警示过的行为。

### 11.2 好消息：追加语义那一半**已经是对的**

第 382–383 行：

```powershell
$result.existingLastRow = Get-LastRecordRow $targetWs $targetInfo.DataStart
$writeStart = if ($result.existingLastRow -gt 0) { $result.existingLastRow + 4 } else { $targetInfo.DataStart }
```

- `Get-LastRecordRow`（第 209–234 行）用 `SpecialCells(2)` 找常量区，对 `B模板.xls`
  会返回 **696**（3 个空行不打断，`Areas` 逐块取 max）；
- 于是 `$writeStart = 696 + 4 = **700**`，**与 §8.1 第 2 项的决策逐字吻合，无需改动**；
- `Assert-WriteRegion`（第 236 行起）的公式/合并单元格检查可直接复用；
- 源列定位 `Find-SourceColumn`（第 65 行）按表头名即可命中 `A模板02` 的
  `A1 = SKU` 与 `D1 = 自定义`，**唯一匹配、无歧义**（`B1 = 父SKU` 不会误撞）；
- 目标列定位 `Find-TargetColumn`（第 188 行）本身也没问题：按叶子名找
  `sku` → 唯一命中 A 列；`平台sku` → 唯一命中 B 列。
  **它只是走不到而已——卡在 B2。**

### 11.4 新发现的格式风险：`SaveAs` 未指定 `FileFormat`

第 401 行 `$targetWb.SaveAs($resolvedOutput)` **不带 `FileFormat` 参数**；
而输出路径的扩展名继承自 `TargetPath`（第 280 行），即 **`.xls`**；
第 300–301 行的工作副本也沿用 `.xls` 扩展名。

`B模板.xls` 实为 xlsx 容器——Excel 打开时按**内容**识别为 xlsx，
`SaveAs` 到 `.xls` 结尾的路径且不指定格式时，输出究竟是
(a) 仍是 xlsx 容器、只是名字叫 `.xls`，还是 (b) 被转成真正的 BIFF8 `.xls`，
**必须实测确认**。若是 (b)，输出与输入格式不同，会改变下游（含 `tests/compare_ooxml.py`）能否读取。
